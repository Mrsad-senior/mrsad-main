## 5.2 Contributions

1. **A model-agnostic enforcement point at the tool boundary.** One decision pipeline serves MCP clients (stdio and streamable HTTP), OpenAI-compatible agents and any framework through the Guard API and Python SDK, so an existing agent is protected by changing a URL or a command.
2. **A policy language for agent actions.** Rules such as "no more than 50 customer records per export" or "e-mail outside the company needs approval" are written as reviewable YAML, validated with line-numbered errors, and activated or rolled back at run time.
3. **Taint tracking with provenance.** Each escalation names the tool, call and field a value came from, so the approver sees evidence instead of the agent's own account of what it is doing.
4. **Arabic-aware detection tooling.** Normalisation handles diacritics, letter variants, Arabic-Indic digits, invisible and bidirectional characters and homoglyphs, and the rules cover Modern Standard Arabic, Gulf dialect and Arabizi alongside English.
5. **Verifiable accountability.** The HMAC hash-chained audit log detects modified and deleted events, and each stored decision can be replayed against its stored policy version and inputs.
6. **Mirsad-Bench.** An offline benchmark with Arabic (MSA and Gulf) and English tasks, five defence configurations, approver models and a replay check, licensed with the rest of the code under Apache-2.0.

## 5.3 Lessons Learned

- **Fixing the interfaces first paid off.** The engineering contract (`docs/dev/BUILD_SPEC.md`) let each workstream code against fixed interfaces, and the defects found during integration clustered at the seams (Section 4.1.13). For example, storing the full taint snapshot in each audit event exceeded the payload cap and would have broken replay, so the gateway now stores a minimal snapshot.
- **A false-positive rate alone hides the cost of a policy.** With {{reports/results_summary.json#bench.scripted_benign_oracle.configs.full.fpr|.1%}} of benign calls denied automatically, {{reports/results_summary.json#bench.scripted_benign_oracle.configs.full.friction|.1%}} still needed a human, mainly because the default policy escalates every external e-mail. Friction must be reported next to the false-positive rate, and it is decided by the policy more than by the detector.
- **Benchmark predicates must be strict.** In the first LLM smoke run, a loose success predicate counted a vague CRM note as a completed task, which showed how easily a benchmark can overstate utility.
- **Arabic needs its own evaluation.** Polite imperatives and forms of address in ordinary Arabic business text overlap with the wording of injected instructions. In a pre-training check, the rules-only fallback flagged more records in the team's Arabic benign batch than in the English one (Section 4.2.2), so every detector metric has to be broken down by language and variety.
- **Process layout changes latency results.** Running the load generator inside the server process inflated tail latency; a separate server process gave a much lower p95 for the same workload. Performance claims must state the layout they were measured with.

## 5.4 Limitations

- **Protection is not yet quantified.** Without attack-labelled data, the evaluation shows what Mirsad costs legitimate work, not how much protection it gives.
- **Evaluation scope.** The scripted agent replays a fixed plan, and the LLM run is a smoke test of {{reports/results_summary.json#bench.llm_smoke.tasks}} tasks rather than an estimate of utility. The oracle approver is an idealised human; real approvers' decision time and quality were not measured, and no user study has been carried out.
- **Taint matching is literal.** Values are recognised only when they reappear verbatim after normalisation, so an agent that paraphrases, translates or re-encodes data defeats value matching. Session-level taint is coarse enough to cause approval friction.
- **Protocol coverage.** Only MCP tools are proxied; resources, prompts and sampling are not, non-text content is dropped rather than inspected, and the OpenAI-compatible proxy does not support streaming.
- **Single-node deployment.** Rate limits live in memory in one process, measurements used SQLite on one laptop, and tail latency under concurrency is high. The Docker Compose deployment was not exercised in the measured environment.
- **Audit and notification gaps.** The log has no retention or erasure mechanism, anchoring of the chain head is manual, and neither Web Push delivery to real phones nor an automated accessibility audit has been tested.
- **Adaptive attackers.** Adaptive attacks have bypassed a wide range of published prompt-injection defences, including detection-based ones [@nasr2026attackermovessecond; @zhan2025adaptive]. Mirsad's policy and taint layers do not depend on recognising attack wording, but no adaptive red-team evaluation has been run against them.

## 5.5 Future Work

1. **Transformer-based Arabic detector.** Once the dataset exists, fine-tune an Arabic or multilingual encoder such as AraBERT, MARBERT, CAMeLBERT or XLM-R [@antoun2020arabert; @abdulmageed2021marbert; @inoue2021camelbert; @conneau2020xlmr], compare it with the n-gram model per language and variety, and distil it if needed to fit the CPU latency budget.
2. **Store-packaged mobile app.** Wrap the approver PWA with Capacitor or rebuild it in Flutter for organisations that require managed apps, adding native push and biometric confirmation of decisions.
3. **Multi-replica deployment.** Move rate-limit counters and live notifications to shared infrastructure (PostgreSQL or Redis), run several workers behind a load balancer, and repeat the concurrency benchmark.
4. **Richer information-flow control.** Replace session-level taint with value-level labels based on lattice information-flow models [@denning1976lattice; @sabelfeld2003language], and offer a CaMeL-style mode in which a plan derived only from the trusted user request constrains later tool calls [@debenedetti2025camel].
5. **Fuller MCP coverage.** Proxy and inspect MCP resources and prompts, handle sampling and non-text content, and track new revisions of the specification [@mcp2026spec].
6. **User study with practitioners.** Measure approvers' decision time and understanding of the bilingual summaries with security practitioners in Saudi organisations, starting from the questionnaire in Appendix F.
7. **Red-team evaluation with adaptive attacks.** Commission an independent red-team exercise that includes adaptive, optimisation-based attacks, and tag test cases and audit events with MITRE ATLAS technique identifiers [@mitre2026atlas].
8. **Certification readiness against NCA ECC.** Close the gaps listed in Appendix A (log retention of at least 12 months, SIEM forwarding, automatic external anchoring of the audit chain, and a formal mapping to the ECC-2:2024 controls [@nca2024ecc]) so that an adopting organisation can use Mirsad's evidence in an assessment.

## 5.6 Concluding Remarks

Mirsad shows that the tool-calling boundary is a workable control point for AI agents. One gateway can apply an organisation's rules to every action an agent takes, explain each decision in Arabic and English, ask a human when the stakes are high, and keep a record that can be verified and replayed. In the benign evaluation it denied {{reports/results_summary.json#bench.scripted_benign_oracle.configs.full.fpr|.1%}} of legitimate calls automatically and added little latency, and its remaining cost comes from policy choices that an organisation can see and tune. Whether this layered design reduces the success of real Arabic and English injection attacks still has to be shown by the attack evaluation, and the benchmark and evidence pipeline are ready to produce that result once the team's data is in place.
